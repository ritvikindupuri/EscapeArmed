Findings
  CRITICAL EA001 Privileged container [PROVEN]
           ea-vulnapp: Container runs with --privileged.
           CVEs: CVE-2025-31133, CVE-2025-52565, CVE-2025-52881
           Fix: Remove privileged mode. Grant only the specific capability or device the workload needs.
  CRITICAL EA002 Dangerous Linux capability added [PROVEN]
           ea-vulnapp: CAP_SYS_ADMIN added: mount, cgroup release_agent, many kernel interfaces.
           Fix: Drop ALL capabilities and add back only what is required. Never add SYS_ADMIN or SYS_MODULE.
  CRITICAL EA003 Container runtime socket mounted [PROVEN]
           ea-vulnapp: Runtime socket /var/run/docker.sock mounted at /var/run/docker.sock (read-write). Read-only does not help, the API is still fully usable.
           Fix: Do not mount runtime sockets. Use a scoped API proxy or a dedicated build service instead.
  HIGH     EA004 Host root filesystem mounted [PROVEN]
           ea-vulnapp: Host / mounted at /host (read-only).
           Fix: Mount only the exact host directory the workload needs, read-only where possible.
  HIGH     EA006 Host PID namespace shared [PROVEN]
           ea-vulnapp: pid: host shares the host PID namespace.
           Fix: Remove pid: host / hostPID: true.
  HIGH     EA013 Root in container without user namespace
           ea-vulnapp: Process runs as UID 0.
           CVEs: CVE-2025-31133, CVE-2025-52565, CVE-2025-52881
           Fix: Run as a non-root USER, and enable user namespaces (rootless Docker, userns-remap, or Kubernetes hostUsers: false).
  HIGH     EA025 Writable host bind mount [PROVEN]
           ea-vulnapp: Host /tmp/escapearmed-demo-share mounted read-write at /shared.
           Fix: Mount host paths read-only, or use a named volume.
  MEDIUM   EA023 Runtime socket writable by non-root on host
           kali: /var/run/docker.sock is writable by group docker (op2rfrc8). Each member is effectively root.
           Fix: Restrict socket permissions and audit the docker group, or use rootless Docker.
  MEDIUM   EA024 Host daemon has no user namespace isolation
           kali: Docker daemon runs rootful without userns-remap.
           CVEs: CVE-2025-31133, CVE-2025-52565, CVE-2025-52881
           Fix: Enable userns-remap or run rootless Docker or Podman.
